## Build model (important)

The UWP build is **not** a single project. It is:

1. **Static-lib projects** (`xenia-base`, `xenia-cpu`, `xenia-gpu`, `xenia-gpu-d3d12`,
   `xenia-ui`, `xenia-ui-d3d12`, `xenia-vfs`, … + third-party libs) — these compile
   the whole emulator. On latest canary these are generated by **CMake**, not premake.
2. **An AppContainer EXE** (`xenia-canary-uwp/xenia-canary-uwp.vcxproj`) that compiles
   only the UWP shim (App.cpp, window/surface/context UWP, UWPUtil, XeniaUWP, the few
   app-level `.cc`) and **ProjectReferences** the static libs above.

The static libs are **not** AppContainer — only the EXE is. The libs only need to be
compiled with `XE_PLATFORM_WINRT=1` and a WinRT-compatible config. We add a cloned
`Release Windows|x64` configuration to every generated lib `.vcxproj` via a **patch
script** (version-independent). See Stage 4.

### Build flow (target)
```
# 1. Generate VS library projects from latest canary CMake (x64):
cmake -S . -B build-vs -G "Visual Studio 17 2022" -A x64 -DXENIA_GPU_D3D12=ON ...
# 2. Patch generated *.vcxproj -> add 'Release Windows|x64' + XE_PLATFORM_WINRT=1:
pwsh tools/uwp/patch_vcxproj_winrt.ps1 build-vs
# 3. Build the AppContainer exe (which pulls in the patched libs):
msbuild xenia-canary-uwp\xenia-canary-uwp.vcxproj /p:Configuration="Release Windows" /p:Platform=x64
```

## Architecture: CLEAN in-tree port (not a copy of the old port)

The old `../xenia-canary_UWP` is a **reference for the problems**, not a source of code.
The UWP backend is implemented **in-tree beside `_win`/`_android`/`_gtk`**, idiomatic
to xenia, with all logic re-designed:

- `base/platform.h` — define `XE_PLATFORM_WINRT` (done).
- `ui/surface.h` — `kTypeIndex_UWPCore` / `kTypeFlag_UWPCore` (done).
- `ui/surface_uwp.{h,cc}` — `UWPCoreWindowSurface` (CoreWindow ABI ptr; HDMI size). (done)
- `ui/window_uwp.{h,cc}` — `UWPWindow` (HDMI sizing + `uwp_present_max_height` GPU cap;
  no input coupling). (done)
- `ui/windowed_app_context_uwp.{h,cc}` — `UWPWindowedAppContext` (CoreDispatcher pump,
  coalesced, liveness-guarded). (done)
- `ui/windowed_app_main_uwp.cc` — `IFrameworkView`/`IFrameworkViewSource` + entry, the
  parallel of `windowed_app_main_win.cc`. (next)
- `ui/d3d12/d3d12_presenter.cc` — guarded `CreateSwapChainForCoreWindow` path.
- ~25 `#if XE_PLATFORM_WINRT` guards for forbidden Win32 APIs (mapped_memory, memory,
  code_cache, file_picker, imgui_drawer clipboard, input).
- Sandbox file access + VFS storage-token resolution — clean re-design.
- Packaging: `package/` with `Package.appxmanifest`, the AppContainer exe `.vcxproj`,
  assets, signing cert (authored fresh, not copied).

> Convergence note: where the platform allows exactly one implementation (e.g. the
> CoreDispatcher pump, the CoreWindow swap chain), the clean version necessarily
> resembles any correct port. That's canonical, not copied.
